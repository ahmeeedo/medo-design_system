Handoff-Dokument

Der Umsetzungs-Vertrag pro Komponente — Varianten, Zustände, Größen und Barrierefreiheit. Verbindlich ist stets die jeweilige Komponenten-Seite; dieses Dokument fasst zusammen.

1 · Tokens einbinden

Single source of truth sind tokens.css (CSS-Variablen, dark-mode-fähig via var()) und tokens.json (aufgelöst, für Style Dictionary / Tailwind / Figma). Alles ist mit Präfix --medo- benannt, in drei Ebenen: Brand (rohe Skalen) → Alias (Rolle→Brand) → Semantic (Material-Stil, in UI-Code bevorzugt nutzen).

/* Semantic-Tokens im UI-Code verwenden */
background: var(--medo-action); /* Primäraktion */
color: var(--medo-action-text);
border-radius: var(--medo-radius-md);
2 · Verbindliche Konventionen
  • Icons: ausschließlich Material Symbols Rounded (weight 300, FILL 0). Keine Inline-SVG-Icons.
  • Schrift: DM Sans (UI/Text), DM Mono (Code/Daten/Labels). Skala 1.25, Basis 16px.
  • Radien: Chips/Tags immer --medo-radius-full; Flächen i.d.R. md/lg.
  • Interaktive Feld-Icons (Clear/Passwort/Kopieren) = Icon-Button-Look (Ruhe stone-100, Hover stone-200, aria-label). Dekorative Icons flach.
  • Nur Light Mode umgesetzt; Token-Architektur ist auf Dark Mode vorbereitet (Semantic-Ebene umdefinieren).
3 · Barrierefreiheit — Baseline (gilt für alle)
  • WCAG 2.2 AA Kontraste (Token-Paare sind darauf abgestimmt).
  • Sichtbarer Fokus: 3px Ring --medo-focus-ring (primary @35%).
  • Voll per Tastatur bedienbar; Trefferflächen ≥ 44px wo sinnvoll.
  • Status nie nur über Farbe — immer Icon/Text ergänzen.
  • Korrekte Rollen/Namen (aria-*), sichtbare Labels bevorzugt.
