Older versions are not supported, but the components still work there, without a few enhancements: entry animations (<Tok>@starting-style</Tok>), text areas that grow with their text (<Tok>field-sizing</Tok>) and finding text in closed accordions (<Tok>hidden="until-found"</Tok>).

Fixes go into the latest version only. Pin a version range that matches how you want to update, e.g. <Tok>"@med-o/ui": "~0.4.1"</Tok> (patches only) or <Tok>"^1.0.0"</Tok> from 1.0.

<DocSection n={3} title="Breaking changes" description="A breaking change says what changed and what to do – in the changelog of the release. What's new lists it first, under “Before you update”.">

```md
## 0.5.0

_Released 2026-11-01_

### Minor Changes

- 1a2b3c4: Improved: `Pagination` names its callback like every other component.

  **Breaking:** `onPageChange` is now `onChange`.
  Update: rename the prop; the value is the same page number.
```

</DocSection>

<DocSection n={4} title="Deprecations" description="Nothing disappears without warning. Old APIs are marked first and keep working for a while.">

```tsx
export interface ButtonProps {
  /** @deprecated Use `variant="ghost"` instead. Removed in 0.6.0. */
  subtle?: boolean;
}
```

<SpecTable
  head={['Step', 'What happens']}
  rows={[
    ['1. Marked', <>The prop, component or token gets <Tok>@deprecated</Tok> with its replacement – your editor strikes it through. The changelog lists it.</>],
    ['2. Still works', 'At least one more minor version while the packages are 0.x; until the next major version from 1.0 on.'],
    ['3. Removed', <>In a later release, marked <strong>Breaking:</strong> in its changelog.</>],
  ]}
/>

A renamed token keeps its old name as an alias for the same time, so no project breaks because of a rename.

</DocSection>

<DocSection n={5} title="Requirements">

<Notes title="What the packages need">
  <ul>
    <li>React 19 and React DOM 19 (peer dependencies).</li>
    <li>ESM only. The components are marked <code>"use client"</code> and work in the Next.js App Router.</li>
    <li>React Aria Components 1.22 or newer (installed with <code>@med-o/ui</code>). <code>Toast</code> builds on React Aria's toast, which React Aria still marks as unstable. Only one file uses it, every React Aria update is tested before we release it, and a weekly CI run builds a Vite and a Next.js app with the newest React Aria – so a change there is found before it reaches you.</li>
    <li>Accessibility target WCAG 2.2 AA in Light and Dark. Please report a violation as a GitHub issue – it is treated as a bug.</li>
  </ul>
</Notes>
