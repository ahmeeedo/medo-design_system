<DocSection n={1} title="Set up" description="Tailwind CSS v4 only – the theme uses @theme, which v3 does not know.">

```css
/* main.css */
@import "tailwindcss";
@import "@med-o/design-tokens/css/tokens.css";      /* the variables, Light and Dark */
@import "@med-o/design-tokens/tailwind/theme.css";  /* maps them to Tailwind */
@import "@med-o/ui/styles.css";                     /* only with the React components */
```

The text style classes (<Tok>medo-text-*</Tok>) from <Tok>typography.css</Tok> are not needed: Tailwind has its own (<Tok>text-body-md</Tok>).

</DocSection>

<DocSection n={4} title="Light and Dark" description="Automatic: every class points to a variable that switches with the theme.">

```html
<!-- Right: one class, both themes -->
<div class="bg-surface-raised text-text-primary">…</div>

<!-- Not needed -->
<div class="bg-white dark:bg-slate-900">…</div>
```

<Tok>dark:</Tok> still exists for the rare case that something must differ beyond the tokens, e.g. another image. It follows the same rule as the tokens: <Tok>data-theme</Tok> first, then the system setting (Guides / Theming).

</DocSection>

<DocSection n={5} title="With components" description="Utilities on a component win over its own styles – cascade layers, not specificity.">

```tsx
<Button className="mt-4 w-full">Save</Button>
<Card className="max-w-(--medo-size-width-xl)">…</Card>
```

Use it for layout around the component: margin, width, position in a grid. Do not restyle colors or inner parts with utilities – change a token instead (Guides / Theming).

</DocSection>
